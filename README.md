# 双岸相机重叠观测的有效时长与补采

这里的资料由本地来源模拟器提供，编号、参与方和历史业务记录全部为合成数据。运行环境为 Node.js 22.23.4，监听地址默认为 `127.0.0.1:8700`，可用 `PORT` 调整端口。

```sh
npm run source
```

另开终端运行 `npm test` 可检查来源契约。测试以独立临时端口启动来源。

两版业务记录和取件字段见 [资料格式](source/formats.md)。`POST /control?edition=r2` 模拟业务方更换当期资料，切回 `r1` 可重新查看初始来源。

本地演练还提供单独的外部接口。用 `npm run provider` 启动，默认地址为 `http://127.0.0.1:8701`，可用 `PROVIDER_PORT` 调整。来源语义、操作回执和演练档见[外部接口](source/provider.md)。

## 值班采集工具

`duty/` 是值班用的采集工具：给它今天关心的水面和时窗，它核出各观察单真正被证明的分钟，趁原图库本轮还开放时领回能填真实空档的相机原图，并协调过岸班次，当天出补采单。

```sh
npm run source &      # 相机目录(8700)
npm run provider &    # 原图库与过岸预约台(8701)
npm run duty -- --window W1 --window W2 --state .duty-state
# 或临时指定水面时窗: npm run duty -- --surface east:60-65
```

一轮的动作：钉定资料版拉全目录流（分页 + ETag 条件请求）→ 核算每分钟有效证据（遮挡否掉、画面格对不上不算；批注只改只数）→ 按真实空档取原图（额度有限、共享图只领一次、完整下载且存储代一致才算）→ 重核覆盖 → 过岸处置（缺口被补图填满的未出发班次凭受理凭据撤并，回读到 released 才把通道转派另一处；已出发班次一律保留）→ 写 `order-<日期>.json` 补采单并打印值班报告。

值班报告按观察单给出：已证明时段与来源画面格、可见无鸟与无证据的区分、缺口可再从哪里取证、现场单受理状态、仍不能覆盖的水面与时间，以及遮挡更正后失效的原时段。状态存在 `--state` 目录，可反复运行，动作幂等。`--settle 毫秒` 可让撤并后等待回读，`--json` 同时打印补采单。
